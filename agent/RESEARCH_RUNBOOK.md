# Unattended Watch update

This privately hosted Watch accepts research on public maritime sources. User notes, onboard records, vessel names and crew information do not enter the feed. Use the Site project linked to the task. The initial deployment uses the owner-private access policy. A future change of audience requires disabling the writer or adding a dedicated writer credential first.

## Access and coverage

Obtain the current live origin and service credential through Sites get_site for the linked project. Confirm the site remains owner-private. In a runtime tool cell retain the credential in memory and send it only to that HTTPS origin as OAI-Sites-Authorization: Bearer followed by the token. Never print its value, place it in a command line, or save it to disk. Send the following requests as a service client. A normal sign-in HTML response, a non-JSON response, or a different origin is a failure. Use a non-redirecting HTTP client.

1. Read GET /api/watch/instructions for the source registry and POST contract. Read GET /data/intelligence.json for known original URLs, versions, run IDs and last attempts.
2. At each three-hour run check IMO (including meeting summaries), Cyprus Shipping Deputy Ministry, Paris MoU and OCIMF. Rotate the other registered sources so each is attempted at least every twelve hours where access permits. Delay retries for repeated 403/429 from a publisher. Respect Retry-After and site access rules. Do not circumvent restrictions. Use the registry's official URLs and primary publications. Searching can discover URLs, but search snippets are insufficient to mark the original checked. Record unavailability and last successful checks separately.
3. Read fresh publications and changed originals. Check date and scope. Record each original once using its canonical HTTPS URL. Use short original English prose. A dated calendar event and a date of entry into force are distinct. Set absent dates to null. Use scope original for source-grounded non-operational information, listing for discovery only, or proposed for legal interpretations, safety-critical advice, operational changes and mandatory checklists. Proposed and listing records retain only metadata in the public reading feed. Keep onboard verification with the officer. Never copy protected questions, restricted documents or full articles. Never submit private data.
4. For a suitable original include a short study note and one three-option quiz with a single supported answer plus explanation. Avoid manufactured daily news. On runs after 06:00 Europe/Warsaw include a short source-based study suggestion when there is a genuine learning item. On Sundays use one run to revisit a previously covered topic and degraded source coverage. Do not create duplicate lessons from an unchanged original.
5. POST /api/watch/runs with Content-Type: application/json and X-Watch-Writer: research-v1, the credential header above and the documented JSON body. Use an immutable ASCII run_id unique to this check. Send a checks entry for each source actually attempted. An empty articles array is valid. A successful source check can have zero articles. Dates of attempt and write are assigned on the server.
6. Read GET /data/intelligence.json again. Confirm runs contains the returned ID, generated_at, counts and expected source state. On an uncertain POST outcome or a concurrent-write conflict, retry the identical ID and payload. If access or verification fails, report that failure and do not claim a successful update. Notify only about substantive, time-sensitive changes with the original link, or repeated whole-service failure.
